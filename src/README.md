# Shared code

`rag_from_scratch/` holds code that more than one day of the series uses.

| Module | Taught in | What it does |
|---|---|---|
| [`ingest.py`](rag_from_scratch/ingest.py) | [Day 02 notebook](../notebooks/day_02_ingestion_and_metadata.ipynb) | Turns the sample files into `Document` records (text with `## ` headings, permissions, provenance, content hash) and a quarantine list |
| [`bm25.py`](rag_from_scratch/bm25.py) | [Day 01 notebook](../notebooks/day_01_rag_foundations.ipynb) | BM25 keyword retrieval over any `{id: text}` mapping, with per-term score contributions |
| [`chunking.py`](rag_from_scratch/chunking.py) | [Day 03 notebook](../notebooks/day_03_chunking_and_structure.ipynb) | Structure-aware chunks: split at `## ` headings, never inside a sentence or table row, `Title > Section` header, stable IDs, inherited metadata |
| [`probes.py`](rag_from_scratch/probes.py) | [Day 03 notebook](../notebooks/day_03_chunking_and_structure.ipynb) | The 13 diagnostic questions with the evidence a chunk must contain to answer each one alone |
| [`embeddings.py`](rag_from_scratch/embeddings.py) | [Day 04 notebook](../notebooks/day_04_embeddings_and_similarity.ipynb) | The pinned local embedding model (`BAAI/bge-small-en-v1.5`): download once, SHA-256 check, `Embedder.embed()` and `embed_query()` returning unit-length 384-number vectors |
| [`index.py`](rag_from_scratch/index.py) | [Day 05 notebook](../notebooks/day_05_vector_search_and_lifecycle.ipynb) | The exact vector index: `VectorIndex` (upsert, update metadata, delete, search with metadata filters before or after the ranking), `groups_filter()`, one-file `save_index()` / `load_index()` with an atomic swap and a model check, and `sync()` that adds, re-embeds, updates and deletes by `chunk_id` and `chunk_hash` |
| [`corpus.py`](rag_from_scratch/corpus.py) | [Day 05 notebook](../notebooks/day_05_vector_search_and_lifecycle.ipynb) | `corpus_after(repo_root, change)`: apply a change to a temporary copy of the sample data, then ingest and chunk it, so a lesson can show document changes without touching `data/sample/` |
| [`answering.py`](rag_from_scratch/answering.py) | [Day 06 notebook](../notebooks/day_06_grounded_rag.ipynb) | The grounded pipeline: `Pipeline.retrieve()` as a user (groups from a directory, permission filter always on) and `Pipeline.answer()` (gate, budgeted context, generator, citation check → answered / abstained / blocked / unavailable), `assemble()`, the API-free `ExtractiveReader`, `check_citations()`, `grade()`. The thresholds are arguments with Day 06's values as defaults |
| [`evaluation.py`](rag_from_scratch/evaluation.py) | [Day 07 notebook](../notebooks/day_07_evaluation_baseline.ipynb) | The evaluation harness: the labelled `Query` and `load_queries()`, the whole-word evidence rule `holds()`, the document `snapshot()` and `validate()`, the metrics `first_relevant()`, `hit()`, `recall()`, `reciprocal_rank()` and `measure()`, the Wilson interval, the sign test, `tie_margin()` and `compare()` against an accepted baseline. `measure()`, `tie_margin()` and `top_score()` take a ranking instead of reading a global |

**How it grows.** Every technique is first written out and explained in the notebook that teaches it. When a *later* day needs it again, a copy moves here, and the later notebook imports it instead of repeating it. The teaching notebooks keep their own full copies.

**How we know the copies are right.** [`tests/test_shared_code.py`](../tests/test_shared_code.py) runs each original notebook's code and checks that the module returns identical results (Day 02: every record and quarantine entry; Day 01: every score and ranking for seven questions; Day 03: every chunk under five size and header settings, the helper functions on made-up edge cases, and the 13 questions; Day 04: every chunk vector with and without headers, questions with and without the query instruction, edge cases such as a text over 512 tokens, and the model-file checks and error messages; Day 05: search results for 19 questions under 10 filter settings, both filter modes and five values of k, every filter condition and its errors, saved files read across versions and every load refusal, and sync plans and resulting indexes for four document changes; Day 06: retrieval for several users, indexes and directories, contexts under six budgets, every answer unit, the reader and the gate under other thresholds and exactly on them, the citation check on 21 replies, whole answers including blocked and failed ones, and the grade; Day 07: the 81 loaded queries, the evidence rule on every query and chunk and on edge cases, the snapshot, every label problem for the real labels, a two-edit change and broken queries, every metric for every query and k, the interval and the sign test over ranges of counts, every margin, and baseline comparisons including the tolerance and near-tie boundaries).

**Memory.** The tests are grouped in one class per day, and each class releases its notebook's variables (including its embedding model) when its tests finish, so only one day's notebook is in memory at a time.

**How to import it.** Nothing to install. Notebooks find the repository root and add `src/` to `sys.path`; `pytest.ini` sets `pythonpath = src` for the tests. In your own script, run from the repository root with `PYTHONPATH=src` (PowerShell: `$env:PYTHONPATH="src"`).

This is teaching code, not a published library: no versioning or API stability promises.
