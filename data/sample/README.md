# Sample corpus: Acme handbook (synthetic)

`acme-handbook/` contains short internal documents for **Acme Corp, a fictional company**. They were written from scratch for this repository so that every learner can run the examples without downloading anything, paying for anything or worrying about reuse rights.

## Day 01 corpus: eight Markdown policies

| File | Owner | Last reviewed |
|---|---|---|
| `remote-work-policy.md` | People Team | 2026-03-02 |
| `expense-reimbursement-policy.md` | Finance | 2026-01-15 |
| `password-and-mfa-standard.md` | IT Security | 2026-05-20 |
| `vpn-access-guide.md` | IT Service Desk | 2026-04-08 |
| `parental-leave-policy.md` | People Team | 2025-11-10 |
| `security-incident-reporting.md` | Security Team | 2026-06-30 |
| `data-retention-policy.md` | Legal | 2026-02-12 |
| `new-starter-it-checklist.md` | IT Service Desk | 2026-07-01 |

Each starts with a small front-matter block (`title`, `owner`, `last_reviewed`) followed by `##` sections. **Day 01 reads only these `.md` files**, so the files added on Day 02 don't change its results.

## Added on Day 02: other formats, with realistic problems

| File | Format | What it demonstrates |
|---|---|---|
| `it-software-requests.html` | Intranet page | Navigation, cookie banner, footer and scripts around the real content; a table that HTML keeps as rows; metadata in `<meta>` tags; a review date more than a year old |
| `travel-policy.pdf` | Text PDF, 2 pages | Running header and footer, a word hyphenated across a line break, and a table drawn column by column; metadata in the PDF document properties |
| `scanned-visitor-policy.pdf` | Image-only PDF | Looks like a document, but has no text layer: extraction returns nothing (OCR needed) |
| `manager-pay-review-guide.txt` | Plain text | No metadata at all; readable only by `managers` and `people-team` |
| `draft-reorg-announcement.txt` | Plain text | A dropped-in draft that claims "please share widely" but has **no** permission entry, so ingestion must fail closed |

Both PDFs are generated by [`scripts/data/make_sample_pdfs.py`](../../scripts/data/make_sample_pdfs.py) using only the Python standard library, so every byte is reproducible and explainable. `tests/test_sample_data.py` checks that the committed PDFs still match the generator. The PDF quirks are built in on purpose; real PDFs show the same problems for many different reasons.

## Permissions: `access-control.json`

`access-control.json` simulates an export of document permissions from Acme's document management system, the **system of record** for who may read what. It maps each file (path relative to `data/sample/`) to the groups allowed to read it. It is deliberately kept **outside** the documents: a file's own text must never decide who can see it. `draft-reorg-announcement.txt` is deliberately missing from it.

Group names (`all-employees`, `managers`, `people-team`) are illustrative.

## Why a fictional company?

A language model cannot have seen Acme's policies during training, because they did not exist. That makes the corpus a clean test of RAG: the only way to answer "How much is the home office allowance?" correctly is to retrieve the right passage.

## Rules

- **Not real policy advice.** Numbers such as "USD 500", "16 weeks" or "USD 220 per night" are invented for teaching.
- **No personal data.** Email addresses and URLs use the reserved `.example` domain (RFC 2606) and cannot reach anyone.
- **Licence:** covered by the repository licence (see the root `README.md`).
- **Changing the corpus changes results.** The notebooks contain sanity checks that expect these exact files. If you edit them, rerun the notebooks and update the checks and slides together.
- **It also changes the ground truth.** The labelled questions in [`evals/`](../../evals/) (Day 07) belong to a recorded snapshot of these files and their permissions. After an edit, `tests/test_evals.py` fails and the Day 07 notebook lists which labels to review; see `evals/README.md`.
